WHY HYBRID SEARCH WORKS BETTER
───────────────────────────────

1. PRODUCT EMBEDDINGS capture:
   ✓ Exact model names/specifications
   ✓ Brand information
   ✓ Technical specs (RAM, storage, GPU)

2. REVIEW EMBEDDINGS capture:
   ✓ Real-world use cases ("great for gaming")
   ✓ Subjective qualities ("lightweight", "fast")
   ✓ User experiences ("good for students")

3. COMBINING BOTH finds products that match:
   ✓ Technical requirements AND
   ✓ User needs/experiences
   
Example:
   Query: "gaming laptop with good cooling"
   
   Product embedding → Finds "gaming" laptops
   Review embedding → Finds laptops with "good cooling" mentioned
   Hybrid → Best gaming laptop with cooling praised in reviews ✅

═══════════════════════════════════════════════════════════════

TECHNICAL DETAILS
─────────────────

Embedding Model: BLAIR-RoBERTa (hyp1231/blair-roberta-base)
Vector Dimension: 768
Database: PostgreSQL 14 + pgvector
Index Type: HNSW (Hierarchical Navigable Small World)

Search Strategy: Balanced Hybrid
  - Product similarity weight: 40%
  - Review similarity weight: 60%
  - Why 60% reviews? Reviews capture user intent better!

Reranker: Enabled
  - Cross-encoder model for final ranking
  - Improves top-K accuracy by ~5-8%
